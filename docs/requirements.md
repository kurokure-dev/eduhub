\# EduHub 요구사항



\## 개요

임직원이 사내 교육과정을 조회·신청하고, 정원이 차면 대기자로 등록되는 시스템.

\- 사용자: 임직원(수강생), 교육 담당자(관리자)



\## 기술 스택

\- 백엔드: Java 21, Spring Boot 3, Spring Data JPA, Flyway, springdoc-openapi, SQL Server

\- 프론트엔드: React 18 + TypeScript, Module Federation(shell, course-mfe, enrollment-mfe), MUI, Axios

\- 빌드: Gradle(Kotlin DSL), npm workspaces



\## 기능 요구사항 (무엇을 하는가)

| FR-02 | 과정 상세와 회차(일정, 장소, 정원, 남은 자리)를 조회한다 | 임직원 | 필수 | 2 |

| NFR-08 | **이해도** | 팀원 누구나 AI 없이 구조와 핵심 파일의 역할을 설명할 수 있다 | 발표 시 확인 |



\## 결정 사항

| ID | 주제 | 결정 | 관련 |
|---|---|---|---|
| D-01 | 취소 | 확정자와 대기자 모두 취소할 수 있다. 대기자가 취소하면 뒷순번이 하나씩 앞당겨진다 | FR-05, FR-06 |
| D-02 | 취소 기한 | 취소는 회차 마감(종료) 전까지만 할 수 있다. 회차의 시작·끝 시점은 따로 관리하지 않는다 | FR-06, D-11 |
| D-03 | 수료 | 확정자만 수료 대상이며, 수료 처리는 관리자만 할 수 있다 | FR-08 |
| D-04 | 회차 종료 | 회차를 종료하면 남은 대기 신청은 자동 취소된다. 종료된 회차에는 신청할 수 없다 | FR-03 |
| D-05 | 정원 증가 | 정원이 늘면 늘어난 수만큼 대기자를 순번대로 자동 승급한다 | FR-03, FR-06 |
| D-06 | 정원 감소 | 정원이 줄면 넘치는 인원만큼 하위 순번 확정자를 대기로 바꾼다 | FR-03, FR-05 |
| D-07 | 재신청 | 취소한 회차에 다시 신청할 수 있으며, 대기가 되면 순번은 맨 뒤다 | FR-04 |
| D-08 | 다른 회차 | 같은 과정의 다른 회차에 동시에 신청할 수 있다 | FR-04 |
| D-09 | 대기 순번 표시 | 신청 내역을 조회하면 현재(바뀐) 대기 순번을 보여 준다 | FR-05, FR-07 |
| D-10 | 수료 시점 | 수료 처리는 회차 마감 뒤라면 언제든 할 수 있다. 수료하지 못한 확정자는 확정 상태로 남는다 (별도의 미수료 상태는 두지 않는다) | FR-07, FR-08 |
| D-11 | 종료의 의미 | 회차 "종료"는 모집 마감이다. 종료 전까지 대기자는 그대로 남는다 | FR-03, D-04 |
| D-12 | 강등 기준 | 정원이 줄면 신청 시각이 늦은 확정자부터 대기로 바꾸고, 내려간 사람은 대기 맨 앞 순번이 된다. 여러 명이 함께 내려가면 그중 신청 시각이 이른 사람이 앞 순번이다 | D-06 |
| D-13 | 강등 알림·정원 변경 시점 | 확정에서 대기로 바뀔 때도 알림을 남긴다. 정원은 회차 마감 전까지만 바꿀 수 있다 | FR-03, FR-09 |
| D-14 | DB 종류 | 프로젝트 DB는 PostgreSQL이 아니라 SQL Server다 (개발 DB: SGY_EHUB). 한글을 저장하므로 문자열 컬럼은 NVARCHAR로 만든다 | NFR-01, NFR-06 |
| D-15 | 테스트 DB | DB 테스트는 Testcontainers 없이 개발 DB(SGY_EHUB)에 직접 연결한다. 접속 정보는 dev와 같은 `.env`를 쓰고, 테스트 데이터는 롤백으로 남기지 않는다 | NFR-01, NFR-05 |

| D-17 | 목록 범위 | 종료된 과정(CLOSED)은 과정 목록에서 뺀다 | FR-01 |
| D-18 | 검색·정렬 | 제목은 부분 일치, 분류는 정확히 일치로 검색한다. 목록의 기본 정렬은 id 내림차순(최신 먼저), 기본 페이지 크기는 10이며 페이지 번호는 0부터다. 클라이언트가 page·size·sort로 바꿀 수 있다 | FR-01 |
| D-19 | 상세의 회차 | 과정 상세에는 모집 중(OPEN)인 회차만 보여 준다 | FR-02, D-11 |
| D-20 | 종료 과정 상세 | 종료된 과정(CLOSED)의 상세를 id로 조회하면 없는 과정과 같이 404로 응답한다 | FR-02, D-17 |
| D-21 | 상세의 회차 순서 | 과정 상세의 회차는 일정(start_date) 오름차순, 같으면 id 오름차순으로 보여 준다 | FR-02, D-19 |
| D-22 | 정렬 허용 필드 | 과정 목록은 id, title, category로만 정렬할 수 있다. 그 밖의 필드로 정렬을 요청하면 400으로 응답한다 | FR-01, D-18 |
| D-23 | 분류 목록 | 분류 목록 API는 종료되지 않은 과정의 분류를 중복 없이 이름순으로 돌려준다. 화면의 분류 선택지는 이 API에서 가져온다 | FR-01, D-17 |
| D-30 | 관리자 권한 | 인증 방식(NFR-03)이 정해지기 전까지 관리자 API는 `/api/v1/admin/**` 경로로만 분리하고 권한 검사는 하지 않는다. 인증을 도입할 때 이 경로에 관리자 권한 검사를 붙인다 | FR-03, NFR-03 |
| D-31 | 과정 종료 | 과정을 종료하면 그 과정의 모집 중(OPEN) 회차도 모두 마감한다. 마감된 회차에는 D-04가 적용된다 | FR-03, D-04 |
| D-32 | 종료 후 변경 | 종료된 과정은 수정·회차 추가를 할 수 없고, 마감된 회차는 일정·장소·정원 모두 수정할 수 없다. 이미 종료·마감된 것을 다시 종료하거나 재개할 수 없다. 이런 요청은 409로 응답한다 | FR-03, D-13 |
| D-33 | 정원 변경과 승급·강등 | 신청 기능이 생기기 전까지 정원 변경은 정원 값만 바꾼다. D-05·D-06의 승급·강등은 신청(enrollment) 기능을 만들 때 정원 변경 처리에 붙인다 (D-38로 갱신) | FR-03, D-05, D-06 |
| D-34 | 관리자 조회와 화면 | 관리자 과정 목록은 종료된 과정도 포함하고 상태로 거를 수 있다. 관리자 과정 상세는 마감된 회차도 보여 준다. 관리자 화면은 별도 앱(`frontend/apps/admin-mfe`, 포트 3002)에 둔다 | FR-03, NFR-07 |
| D-24 | 화면 주소 | course-mfe는 react-router로 화면을 나눈다. 목록은 `/courses`, 상세는 `/courses/{id}`이고 `/`와 없는 경로는 `/courses`로 보낸다. id가 양의 정수가 아니면 API를 부르지 않고 없는 과정으로 표시한다 | FR-01, FR-02 |
| D-25 | 목록 상태 유지 | 목록의 검색어·분류·페이지·페이지 크기는 URL 쿼리(`keyword`, `category`, `page`, `size`)에 둔다. 상세에서 뒤로 가거나 새로고침해도 같은 목록이 보인다. 기본값(빈 값, page 0, size 10)은 쿼리에서 뺀다 | FR-01, D-18 |
| D-26 | 상세로 이동 | 목록에서는 과정 제목을 상세 링크로 만든다 (행 전체 클릭은 쓰지 않는다) | FR-01, FR-02 |
| D-27 | 상세의 신청 버튼 | 신청 기능(FR-04)이 생기기 전까지 회차 표에는 비활성 "신청" 버튼만 둔다. FR-04에서 동작을 붙인다 | FR-02, FR-04 |
| D-28 | 상세의 빈 결과·오류 | 404(없거나 종료된 과정)는 "과정을 찾을 수 없습니다"와 목록 링크로, 그 밖의 오류는 오류 메시지로 구분해 보여 준다. 모집 중인 회차가 없으면 표 안에 "모집 중인 회차가 없습니다"를 보여 준다 | FR-02, D-19, D-20 |
| D-29 | 회차 직렬화 지점 | 정원은 course의 회차(course_session) 행이 소유한다. 신청·취소·승급·강등·마감 처리는 해당 회차 행을 비관적 락(SQL Server UPDLOCK)으로 잡은 뒤 진행한다. enrollment는 course를 단방향으로만 참조한다(course→enrollment 의존 금지) | NFR-01, NFR-07, FR-04 |
| D-35 | FR-04 범위 | FR-04는 신청 API와 동시성 처리까지 만든다. 남은 자리가 있고 대기자가 없으면 확정, 그렇지 않으면 대기(WAITING)로 저장한다. 대기 순번 부여·응답(FR-05)과 취소·승급(FR-06)은 다음 기능에서 만든다 | FR-04, FR-05 |
| D-36 | 신청자 식별 | 인증 방식(NFR-03)이 정해지기 전까지 신청자는 요청 본문의 `employeeId`(사번, 최대 20자)로 받는다. 본인 확인은 하지 않는다. 인증을 도입할 때 현재 로그인 사용자로 바꾼다. 서비스는 사번을 인자로 받고, Controller에 `TODO(NFR-03)`를 남긴다 | FR-04, NFR-03 |
| D-37 | 확정 인원 | 회차(`course_session`)에 확정 인원 `confirmed_count`를 두고 회차 행 락 안에서만 바꾼다. 과정 상세의 남은 자리는 `capacity - confirmed_count`다 (D-16 대체) | FR-02, FR-04, D-29 |
| D-38 | 임시 제한 | 확정자가 있는 회차는 정원을 바꿀 수 없다(409, 일정·장소는 바꿀 수 있다). 마감 시 대기 자동 취소(D-04)와 정원 증감에 따른 승급·강등(D-05, D-06)은 FR-06에서 붙이며, 그때 이 제한을 푼다 (D-33 갱신) | FR-03, FR-06, D-33 |
| D-39 | 대기 정렬 키 | 대기 순서는 신청 시각이 아니라 `waiting_order`(회차 안에서 유일한 정수)로 정한다. 새 대기는 회차의 현재 최대값 + 1(없으면 1), 강등자는 최소값 - 1로 앞에 넣는다. 대기 순번은 같은 회차의 대기 중 자신 이하 키의 개수다. 키 부여는 FR-05에서 한다. 그 전에 저장된 대기 신청은 FR-05 마이그레이션이 `applied_at, id` 순으로 채운다 | FR-05, D-09, D-12 |
| D-40 | 동시성 테스트 | 동시성 테스트(NFR-01)는 실제 동시 트랜잭션이 필요하므로 D-15의 예외로 개발 DB에 커밋하고 테스트가 끝나면 지운다. `@Tag("concurrency")`를 달아 기본 `./gradlew test`에서 빼고, 사람이 `./gradlew concurrencyTest`로 직접 실행한다. 중단돼 남은 데이터는 제목이 `동시성테스트-`로 시작하는 과정으로 찾아 지운다 | NFR-01, D-15 |
| D-41 | 배포 제한 | 인증(NFR-03)과 취소(FR-06)가 생기기 전까지 신청 기능은 개발 DB에서만 쓰고 공유·운영 환경에 배포하지 않는다. 본인 확인 없이 아무 사번으로 정원을 채울 수 있고, 취소 API가 없으며 D-38 때문에 정원도 늘릴 수 없어 되돌릴 수단이 회차 마감뿐이기 때문이다 | FR-04, NFR-03, D-36, D-38 |
